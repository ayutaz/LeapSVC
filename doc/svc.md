# LeapSVC 調査・設計ドキュメント索引

最終更新: 2026-09-01

対象ブランチ: `main`（旧 `feature/svc`。2026-09-18 に merge して削除）

## 結論

このブランチでは、既存の LeapSinger の「音素・duration・F0 から mel を作る歌声合成（SVS）」を残したまま、事前計算済みの content feature・F0・V/UV・音量から target singer の mel を生成する、オフライン歌声変換（SVC）経路を追加しています。

現時点でモデル、データ契約、学習・評価・単体推論の配線に加え、**実音声から特徴量を作る前処理**（WAV からコマンド 1 本、再実行で bit 一致）、**23 話者・約 18 時間の multi-singer base 事前学習（60,000 step）**、そこからの **target singer（波音リツ）への fine-tune（20,000 step）**まで到達しています。未知の source singer を入れても内容が崩壊しないことを実測しました。実行環境も Python 3.13 と `uv.lock` で固定しています（[実装状況](svc-implementation-status.md) の「実行環境」表）。

話者類似度も測れるようになりました（2026-09-01）。ECAPA-TDNN を 12 秒以上のクリップで使うと事前登録した較正条件を満たし、**fine-tune で target らしさが上がっている**ことを確認しています（回復率 45.1% → 54.9%）。

**M5（Seed-VC 比較）は完了し、完了レベル 4 に到達しました**（客観 26 clip + blind
preference 26 ペア）。~~話者類似度では Seed-VC が上回り~~ という記述は**取り下げました** ――
**測定に上限が混ざっていた誤り**で、訂正後は **0.5899 対 0.5912 でほぼ同等**です。さらに
**主観でも判別できませんでした**（2026-09-15。「どちらが target 本人に似ているか」を別の
質問として聴取し、判定 4 票すべてが「後に聴いた側」に張り付いて判定に至らず）。

**それでも「Seed-VC より良い」とは書けません。** 理由は**話者類似度ではなく blind
preference で負けている**ことです（25 判定中 21）。その差は**明るさ**で説明が付き
（Seed-VC は target 本人の録音より 1.85 倍明るい）、**明るさは target 忠実を採ると決めた**
ので、モデル側では足しません。**F0 追従・V/UV・timing は LeapSVC が上**で、F0 を条件として
直接与える設計の表れです。詳細と限界は [実行計画](svc-plan.md) M5 の進捗節。

**未知話者の日本語でも通用します（2026-09-17、n=20）。** 東北きりたん / No.7 を取得して
**初めて未知話者として測り**、音量を合わせた条件で **明瞭度は上限との差 +7.3 点、話者類似度の
回復率 90.4%、明るさは上限比 0.93x** でした。**既知話者（+8.9 点 / 90.8%）と同等以上**です。

**明瞭度で動くのは「その曲を学習で見たか」だけでした。** 切り分けの結果:

| 変えた軸 | 明瞭度は動いたか |
|---|---|
| `num_steps`（1 → 16）/ GAN の有無 / fine-tune の step / base の学習量 / **話者の既知性** | **動かない** |
| **その曲を学習で見たか** | **動く**（学習曲 +1.0 点 対 未知曲 +7.3〜+11.1 点） |

**したがって base を作り直す計画（案 B）は実施しません。** 話者を足しても、話者の既知性が
効いていないので動く見込みがありません。**8〜12 時間と $2〜3 を使わずに済みました。**

**商用リリースの可否も調べました（2026-09-19〜20）。** 結論は
[商用リリースのデータ要件](commercial-release-data.md) にあります。**塞いでいるのはデータの量
ではなく 2 つの部品の権利**で（同梱ボコーダー NHVSing の重みが非商用、base の素材 GTSinger が
CC BY-NC-SA）、**商用可の歌唱素材は実測 29.2 時間 / 40 話者**（由来に懸念のある SingVERSE を
除くと 20.1 時間 / 23 話者）――**現 base（23 話者・18 時間）と同規模の作り直しは素材の面では
可能**です。ボコーダー側も**上流が学習コードと配布重みのレシピを MIT で公開**しており、
**mel 契約が完全一致**することをコードで確認しました。

**利用者が持つ 1,000 時間級の日本語素材（YouTube 由来）は、実際に学習して答えを出しました。**
事前登録した 2 つの判定（[実行計画](svc-plan.md) 12 節）は**両方とも不合格**でしたが
（低音域は入っておらず C3 未満の中央値 1.224%、分離ボーカルは上限が別物で mel L1 0.5279）、
**利用者の判断で中止条件を解除**し、**462 話者・約 40 時間で base を 60,000 step 学習**しました
（13 節）。

**結論: この素材は base に向きません。** 現 base（23 話者）と同条件で比べて、
**明瞭度は変わらず**（差の中央値 +0.8 点、3/6、p = 1.0000）、**明るさは悪化**
（\|上限比 − 1\| 0.157 → 0.231）、**話者類似度は大きく悪化**（回復率 **77.9% → 30.1%**）。
事前登録した規則 2 が発動したので、**追加投入は行いません。**

**予測は半分外れました** ―― 明瞭度の「変わらない」は当たり、**話者類似度は「上がる可能性」と
書いたのに逆へ大きく動きました**。仮説は `balance_speakers` で target の取り分が
1/23 → 1/462 になったことですが、**未検証**です。**これは base どうしの比較**で、
target fine-tune 後も劣るかは確かめていません。

**未完了なのはリアルタイム student（M6）だけ**で、これは 2026-09-14 に**直列経路から外し、
起動条件つき**にしました。**男声や低音の未知話者**も測れていません（取得した 2 名は女声で、
target とほぼ同音域でした）。
**streaming（M6）は 2026-09-14 に直列経路から外し、起動条件つきにしました**（must ではない）。
したがって「リアルタイム動作」も「Seed-VC より高品質」もまだ確認済みの成果ではありません。
**推論 RTF の実測（GPU で合計 0.464、CPU で 0.654）も「リアルタイム」の根拠になりません** ――
chunk 境界・audio I/O・連続運転を測っていないためです。**GPU ではボコーダーが合計の 93%**
を占めるので、acoustic を速くしても end-to-end はほとんど動きません。

## 主要な決定事項

| 項目 | 決定 |
|---|---|
| 製品目標 | zero-shot 万能モデルではなく、追加学習可能な target-singer SVC |
| 最初の品質目標 | まず offline teacher を完成させ、Seed-VC と比較する |
| streaming | offline 品質ゲート通過後に causal / limited-lookahead student を蒸留する。**2026-09-14 に直列経路から外しました** — **must ではなく、品質が十分になってから**（[起動条件](svc-plan.md#m6-streaming-student)） |
| 既存 SVS | 削除せず、`model.arch: svc` の別経路として維持する |
| content encoder | **ContentVec**（`lengyue233/content-vec-best`、MIT、768 次元 layer 12）を凍結して使う。学習は 768 から固定ランダムに選んだ **256 次元**を既定とする（[根拠](svc-content-encoder.md)） |
| pitch | **RMVPE に固定**して source F0 と V/UV を抽出する |
| vocoder | NHVSing と互換な 44.1 kHz・hop 256・128-bin ln-mel を出力する |
| 学習順序 | multi-singer base の事前学習を推奨し、target singer へ fine-tune |
| 学習環境 | 学習は vast.ai の Linux GPU インスタンスで行う。手元の Windows 機は開発・推論・検証用 |
| 用途と配布 | **研究・個人利用のみ、モデルの配布なし**。非商用ライセンスのコーパスも使える（[台帳](svc-dataset-ledger.md)） |
| 素材 | base は **GTSinger**（80.6 h / 20 歌手 / 48 kHz / 実録音）、未知 source の test は **VocalSet**、target は既存 3 DB |
| 話者類似度 | **ECAPA-TDNN を 12 秒以上のクリップで使う。** 較正表（同一話者 / 別話者・同性 / 別話者・異性の重なり）を示さずに cosine を「話者類似度」として報告しない |
| M5 の判定 | **guard rail 方式。** 主要判定は blind preference、客観 4 指標は悪化の検出に使う。**preference で勝っても guard rail を落としていたら「より良い」と書かない** |
| 客観指標の読み方 | **絶対値を品質として報告しない。** 上限（GT mel をボコーダーに通した再合成）との差で読む。CER と信号品質は**上限が無ければ実行そのものを拒否**する |
| checkpoint 選択 | **train loss だけで選ばない。** 選択規則を実験前に config へ書き、未知 source の内容保持が base から一定以上落ちた checkpoint は候補から外す（M4 で実際に発動） |
| 低い声からの変換 | **`--transpose` に +7 を渡す**（`tools/svc_defaults.py` の `SVC_TRANSPOSE_LOW_VOICE`。2026-09-16 の掃引で ~~+7〜+12~~ から確定）。**+12 は話者類似度も明瞭度も劣る**（回復率 90.8% → 81.6%、CER の上限との差 +12.5 → +27.0 点）。移調なしの数値で品質を判断しない |
| 持ち込み音源 | **`--match-loudness` を付ける。** 配信用に限らず**プロのスタジオ録音でも**要ります（きりたん / No.7 は学習分布から中央値 +0.60 σ ずれ、付けないと明るさが上限比 0.71x、付けると 0.93x） |
| 上限（`*_vocoder_only.wav`） | **1 度だけ作って系をまたいで使い回す**（`--ceiling-from`）。NHVSing の ONNX が **seed の無い乱数**を持つので、作り直すと必ず変わります（**CPU + 決定的モードでも一致しません**） |
| 主観評価 | **anchor（catch trial）を混ぜる。** 入れないと「2 系が同一」と「評価者が判別できていない」を区別できません。**集計では side の偏り（`p_side`）も見る** |
| 完了判定 | コードの存在ではなく、実音声・比較試聴・遅延実測まで段階別に判定する |

## 未決事項

- speaker embedding を fine-tune 後も残すか、target 固定モデルへ焼き込むか。
- offline teacher の合格閾値と、許容する streaming lookahead / 往復遅延。
- 256 次元部分集合の seed 0 と seed 1 の差（**1 度比較して seed 1 が良い方向だったが、各 1 run では部分集合の差と run のばらつきを分離できない**。**反復は未実施のまま M4 まで進みました**。seed 0 を既定として据え置いています）。
- ~~話者類似度をどう測るか~~ — **決着（2026-09-01）。** ECAPA-TDNN（`speechbrain`、`eval` extra）を **12 秒以上**のクリップで使うと、事前登録した合格条件（重なり 20% 以下）を満たします。較正は [`tools/speaker_calibrate.py`](../tools/speaker_calibrate.py) で再実行できます。**encoder と長さの両方が要ります**（x-vector は 12 秒でも 77.0% で不合格、ECAPA も 6 秒では 56.9% で不合格）。
- ~~話者性を上げる手~~ — **`num_steps` は実施しました（2026-09-01）。** 既定を 16 にして
未知 source の回復率が 60.7% → **69.4%**、timing も 66.2% → **71.9%**（Seed-VC を上回る）。
**話者類似度は Seed-VC とほぼ同等です**（訂正後 0.5673 対 0.5912。旧 0.4910 は測定誤り）。guard rail は落ちたままです。
- ~~GAN を有効にするか~~ — **fine-tune で実施しました（2026-09-02、案 A）。** 未知 source の
回復率が 69.4% → **75.3%**、timing も 73.7% で Seed-VC（70.8%）を上回ります。**過平滑が主因
だったことの確認**になりました。**話者類似度は Seed-VC とほぼ同等です**（訂正後 0.5886 対 0.5912。旧 0.4981 は測定誤り）、
guard rail は落ちたままです。
- ~~案 B（base から GAN 付きで学習し直す）へ進むか~~ — **実施しないと決めました（2026-09-17）。**
**未知話者でも既知話者と同等**だと測れたためです（明瞭度 +7.3 対 +8.9 点、回復率 90.4% 対
90.8%、n=20）。**話者の既知性がほとんど効いていない**ので、base に話者を足しても動く見込みが
ありません。また `num_steps`・GAN の有無・fine-tune の step・**base の学習量**のいずれも
明瞭度を動かしませんでした。**動くのは「その曲を学習で見たか」だけ**です
（[実行計画](svc-plan.md#2b-ここからの計画)）。
- **残る唯一の仮説は「曲（歌詞・旋律）の多様性」**です。ただし確かめるにも base の再学習が
要り、**「学習の量では動かない」と分かっている**ので期待値は低いです。
- ~~低音 source の移調量~~ — **決着（2026-09-16）。+7 半音。** 掃引で決めました
（`SVC_TRANSPOSE_LOW_VOICE`）。**それまでの +12 は両方の軸で劣ります。**
- **男声や低音の未知話者をどう測るか**（**要ユーザー判断**）。取得した 2 名は**女声で target と
ほぼ同音域**（336 / 324 Hz 対 360 Hz）で、**C3 より下は 0.0%** でした。**低音域の欠落は
解消していません**（低音を担うのは夏目悠李だけ）。素材の取得が要ります。
- ~~target 類似を主観でも測るか~~ — **実施しました（2026-09-15）。判定に至らず。**
6 / 12 ペアで中断し、**判定 4 票のすべてが「後に聴いた側」**でした（A 0 / B 4）。評価者の報告は
**「意味がないように思えます。同じボイスをずっと聞かされています」**。**「Seed-VC のほうが
似ている」という結果は出ていません**が、**「同等」とも書けません**（n = 4 + 位置の偏り）。
**前回の preference は位置の偏りでは説明できません**（A 10 / B 15、p_side = 0.4244 に対し
系は p = 0.0009）。**同一性は客観でも主観でも差が無く、当面の梃子ではありません**
（[実行計画](svc-plan.md#2b-ここからの計画) の①）。
- ~~M6 をどう始めるか~~ — **決着（2026-09-14）。直列経路から外しました。** must ではなく、
**品質が十分になってから**着手します。起動条件は「同一 test set の blind comparison で
preference が baseline を上回り、guard rail を 1 つも落としていない」こと
（[実行計画](svc-plan.md#m6-streaming-student)）。着手すると決めたときの**最初の作業は蒸留では
なくボコーダーの実行経路の測定**です（GPU の end-to-end RTF 0.464 のうち**ボコーダーが 93%**）。
- **外部 baseline を Seed-VC 以外へ広げるか**（**要ユーザー判断**）。品質の到達点を外部基準で
言うなら 1 系では足りません。候補は RVC / So-VITS-SVC / Beatrice で、**Beatrice は同じ手元で
動いています**。**「SOTA」は目標としては明確ですが、文書には軸と比較対象と test set を明示した
記述として書きます**（[主張ルール](svc-prior-art-license.md) 6 節）。
- ~~CER の +0.168 を分解するか~~ — **1 を実施しました（2026-09-15）。** 公表値 **+0.168 は
言語の混合**でした（test set は日本語 6 / ラテン語 10 / イタリア語 5 / 英語 5 で、ラテン語は
**上限自身が 23% 揃わない**）。訂正後は **日本語 +5 点前後 / 英語 +10〜19 点**（n=4〜6）。
**ただし上限が run をまたいで再現しないため、系間比較はまだできません**（同じ V3 で 26 clip 中
6 本が 5 点超ずれ、最大 88 点）。**次は上限を 1 度だけ作って共有すること**
（[実行計画](svc-plan.md#2b-ここからの計画) の 1a）。
- ~~上限を系間で比べられるようにするか~~ — **完了（2026-09-15、1a）。** 原因は
**NHVSing の ONNX に seed 属性の無い `RandomNormalLike` がある**こと（ボコーダーが自分で
ノイズを生成する）でした。**CPU + 決定的モードでも bit 一致しません。**
`tools/svc_convert.py --ceiling-from <dir>` で**上限を作り直さず使い回せる**ようにし、
`convert.json` が `ceiling_comparable` を申告するようにしました。
**残りは M5 の 26 clip を共有の上限で変換し直すこと**です。
- ~~主観テストの anchor~~ — **完了（2026-09-15、1b）。** `blind_test.py prepare
--anchor-target / --anchor-foil` で catch trial を混ぜられます。正解は `anchors.json` だけに
置き、`tally` が**合格線 75%** で「本番の拮抗を『2 系が同一』と読まないこと」を警告します。
- **男声 source の transpose を掃引するか**（**推奨**）。明瞭度が最も崩れるのは **男声 +12 半音**
です（英語 6 本のうち男声 2 本が +16.0 と +100.0 点、女声 4 本は +0.0〜+20.3 点）。いま全部の
男声に +12 を渡していますが、根拠は「+7〜+12」という範囲だけで**掃引していません**。
**再学習なしに既定を決め直せます**（[実行計画](svc-plan.md#2b-ここからの計画) の 2a）。
- **入力 F0 に対する出力スペクトル傾斜の結合をモデル側で緩めるか。** 変換時の移調（`--transpose`）で実用上は回避できており、**fine-tune では緩みませんでした**（M4 で実測）。緩めるには**特徴抽出前**の pitch augmentation が要ります（**未実装**。SVC では online `pitch_aug` を使えません）。
- ~~M5 の合格条件と主観評価の条件~~ — **決着（2026-09-01、測定の前に決定）。** 判定は **guard rail 方式**（主要判定は blind preference、客観 4 指標は「Seed-VC より clip 間ばらつきを超えて悪化していないこと」）。主観評価は **N=1 の非公式 preference test**（MOS とは呼ばない）。test set は **20 clip / 12 秒以上 / 日本語を含む / 同性・異性の両方**。詳細は [実行計画](svc-plan.md) M5「事前登録した判定規則」。

**決着済み（2026-08-30）:** 補間方法は **left（直前保持）**、256 次元の部分集合は **seed 0 を既定**、
`content-vec-best` は **layer 12 の hidden state（768 次元・50 Hz）を実モデルで確認**、
**NHVSing は既存重みをそのまま使う**（GTSinger に out-of-distribution なペナルティは
観測されなかった。[台帳 7b 節](svc-dataset-ledger.md#7b-nhvsing-にとって-in-distribution-かの実測2026-08-30)）、
用途は**研究・個人利用のみ**、素材は **target = 波音リツ / base = GTSinger + 日本語 3 DB /
未知 source test = VocalSet** に確定しました（[content encoder の選定](svc-content-encoder.md)、
[データセット台帳](svc-dataset-ledger.md)）。

### M5 の後（2026-09-14〜17）: 診断と既定の更新

**M0〜M5 の後に、品質の律速を切り分けました。** 詳細は [実行計画](svc-plan.md#2b-ここからの計画)。

| 実施 | 結果 |
|---|---|
| **① target 類似の blind** | **判定に至らず**。判定 4 票すべてが「後に聴いた側」で、評価者は「意味がない」と述べた。**anchor（catch trial）が無かったのが原因**（実装済み） |
| **③ CER の分解** | 公表値 **+0.168 は言語の混合**だった。訂正後は日本語 +5 点前後 / 英語 +10〜19 点。**上限がボコーダーの乱数で run ごとに変わる**ことも判明（`--ceiling-from` を実装） |
| **2a 移調の掃引** | **既定を +12 → +7 に変更**（`SVC_TRANSPOSE_LOW_VOICE`）。**+12 は両方の軸で劣る** |
| **2b/2c/2d 切り分け** | 明瞭度は **fine-tune の step でも base の学習量でも動かない**。**eval/loss は明瞭度の代理にならない**（0.02311 → 0.01459 でも明瞭度は不変） |
| **A 未知話者の日本語** | **既知話者と同等以上**（明瞭度 +7.3 対 +8.9 点、回復率 90.4% 対 90.8%、n=20）。**案 B は実施しないと決定** |

**動くのは「その曲を学習で見たか」だけ**でした（学習曲 +1.0 点 対 未知曲 +7.3〜+11.1 点）。

**決定（2026-09-13）: 明るさは target 忠実を採ります。** blind の選好は明るさの差
（Seed-VC は target 本人の録音より 1.85 倍明るい）で動いていました。**明るくすれば選好は
取れますが target から離れる**ため、モデル側では明るさを足しません。聴いたときの大きさは
ミックス段で扱います。**レベルを上げても直らない**点に注意（原因は明るさであってレベル
ではありません）。
