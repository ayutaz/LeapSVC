# 商用リリースに向けたデータ検証のまとめ

期間: 2026-09-19 〜 2026-09-26

対象: ブランチ `docs/commercial-release-data`

この文書は、**「商用利用できるモデルとして出すには、どんなデータがどれだけ要るか」**を
机上の調査だけでなく**実際に学習して確かめた**記録のまとめです。

- 机上の調査（素材の棚卸し・ライセンス・費用）: [商用リリースのデータ要件](commercial-release-data.md)
- 各実験の事前登録・判定規則・生の結果: [実行計画](svc-plan.md) の **12〜15 節**
- 権利条件の一次資料と問い合わせ文面: [データセット台帳](svc-dataset-ledger.md)

> **この文書は法的助言ではありません。** 権利の判断は「問い合わせの回答は来ない」という
> 利用者の前提（2026-09-21）のもとで、**公開されている条文だけ**に依拠しています。

## 1. 結論（先に読む）

**確認済み（4 回の学習実験、根拠は 4 節）: 今の品質を保ったまま商用版を作るには、
「歌詞のある曲を、スタジオ品質で、1 人あたり十分な量」歌ってもらった録音が要ります。**
公開されている商用可の素材だけでは足りません。

| | 答え | 確度 |
|---|---|---|
| **どんなデータか** | 歌詞のある楽曲を、スタジオ品質で、1 歌手あたり約 45 分 | **確認済み**（歌詞の必要性）/ **仮説**（質と量のどちらが効くか） |
| **どのくらいか** | 現 base の形に合わせて **約 20 歌手 × 0.75 h ≈ 15 h** | **見積もり**（少なくて済むかは未検証） |
| **費用** | 収録費だけで **約 ¥22 万〜100 万**（歌唱料・権利の買い取りは別） | **見積もり**（歌唱料の相場は未調査） |
| **公開素材で足りるか** | **足りない**。商用可の公開素材の中心は VocalSet（音階・発声練習）で、歌詞のある楽曲のスタジオ録音がほぼ無い | **確認済み**（S1） |

**曲の権利:** 童謡・クラシック（パブリックドメイン）か自作曲にすれば、楽曲側の権利は不要です。

**データとは別に、ボコーダーの問題が残っています。** 同梱の NHVSing は**重みが非商用**なので、
商用版では権利クリーンな素材での再学習（[データ要件](commercial-release-data.md) 8 節の S2）が
必要です。**これは未着手**で、本文書の実験はすべて既存の NHVSing V3.1 で評価しています。

## 2. 分かったこと

**確認済み（1）: データを増やしても良くならない。** YouTube の歌声 462 人・約 40 時間で
学習しても、**歌詞の聞き取りやすさは今と変わらず**、**リツの声への似せ方は大きく悪化**
しました（P1）。「とにかく大量に集めればいい」は、このモデルでは成り立ちません。

**確認済み（2）: 「歌詞を歌っている音」が要る。** 商用可の公開素材（中心は VocalSet の
音階練習）だけで作ると、**歌詞の聞き取りやすさが大きく落ちました**（S1）。同じ形のまま
中身だけを**歌詞のある曲**へ替えると、**落ちた分の約 3 分の 2 が戻りました**（S1b）。
**必要なのは歌詞の注釈ではなく、歌詞を実際に歌っている音声**です ―― SVC はテキストを
一切読まず、音声から音素的な特徴（ContentVec）を取るためです。

**確認済み（3）: 歌詞があるだけでは足りない。** 歌詞つきに替えても、**声の似せ方と
音の明るさは戻りませんでした**（S1b）。

**仮説（4）: 残る差は「録音の質」か「1 人あたりの量」。** S1b の cover 素材は
**配信音源から分離したボーカル**で**1 人約 4 分**、現 base の GTSinger は
**スタジオ録音**で**1 人約 45 分**です。**どちらが効いているかは切り分けていません。**
分離ボーカルの上限が既存素材と別物であることは実測済みです（P0-3）。

**確認済み（5）: 学習の loss は品質の代わりにならない。** S1 の loss は P1 より低いのに
（flow 0.0055 対 0.0150）、品質はより悪い結果でした。この開発で 3 度目の実例です。

## 3. 進め方と評価の条件

**決定: どの実験も「測る前に判定規則と予測を書き、結果が外れても書き換えない」順で行いました**
（[実行計画](svc-plan.md) 12〜15 節に日付つきで登録）。

**評価の共通条件（確認済み）:** 波音リツの**学習に入れていない 3 曲**から切り出した
**6 clip（各 20 秒）**を、各モデルでリツの声へ変換して比べます。`num_steps 16`・CPU・
ボコーダーは NHVSing V3.1。**「上限」**（正解の mel を同じボコーダーに通した音）は
`out/m5/where_base60000` のものを `--ceiling-from` で**全実験で使い回し**ています
（`ceiling_comparable: true`）。正規化統計は全実験で `m3c` の manifest に揃えました。

| 指標 | 意味 | 良い向き |
|---|---|---|
| **明瞭度** | 歌詞の聞き取りやすさ。ASR の文字誤り率（CER）の、上限との差の**差の中央値** | 小さいほど良い |
| **話者類似度（回復率）** | どれだけリツ本人の声に似ているか（ECAPA-TDNN、20 秒） | 大きいほど良い |
| **明るさ** | 声の明るさが本人の録音からどれだけ外れるか（spectral centroid の \|上限比 − 1\|） | 小さいほど良い |

**比較の相手（現 base）:** 23 話者・約 18 時間（GTSinger 20 名 + 日本語 3 DB）で 60,000 step
学習した `m3_base`。checkpoint は `.m0data/m3c/ckpt_060000.pt`。

## 4. 実験と結果

### 4.1 一覧

| 実験 | 素材 | 問い | 判定 | 予測 |
|---|---|---|---|---|
| **P0-2** | 利用者の YouTube 素材（n = 75 曲） | 低音域の男声が入っているか | **不合格**（C3 未満の中央値 1.224% < 3.6%） | 外れ |
| **P0-3** | 同・分離ボーカル（12 clip） | 上限が既存素材と同じか | **不合格**（mel L1 0.5279 対 0.2929〜0.3371、p = 0.000002） | 外れ |
| **P1** | YouTube cover 462 人 + リツ（約 40 h） | 大量の話者で良くなるか | **向かない**（規則 2 発動） | 半分外れ |
| **S1** | 商用可の公開素材 16 人（約 16.4 h） | 権利クリーンな素材で再現できるか | **不合格**（規則 2 発動） | 外れ |
| **S1b** | S1 の音階練習 14 人を歌詞つき cover 14 人へ差し替え | 効いたのは「歌詞のある音か」 | **支持**（規則 1、65% 戻る） | 当たり |

**P0 の 2 つが不合格でも P1 を回したのは、利用者の判断で中止条件を解除したため**です
（2026-09-20）。**判定そのものは書き換えていません。**

### 4.2 学習実験の結果（同一条件）

| 指標 | 現 base | P1 | S1 | **S1b** |
|---|---:|---:|---:|---:|
| 素材 | 23 話者 / 18 h | 462 話者 / 40 h | 16 話者 / 約 16.4 h | 16 話者 / 約 11 h（推定） |
| 中身の主体 | GTSinger（歌詞つき・スタジオ） | YouTube cover（分離） | **VocalSet（音階練習）** | **YouTube cover（歌詞つき・分離）** |
| step | 60,000 | 60,000 | 50,000 | 50,000 |
| **明瞭度**（上限との差） | **+25.5 点** | +29.9 点 | +50.5 点 | **+34.2 点** |
| **話者類似度**（回復率） | **77.9%** | 30.1% | 49.2% | 47.5% |
| **明るさ**（\|上限比 − 1\|） | **0.157** | 0.231 | 0.199 | 0.210 |

**確認済み（対応のある比較、6 clip）:**

| 比較 | 明瞭度の差の中央値 | 良くなった clip | Wilcoxon |
|---|---:|---:|---:|
| P1 − 現 base | +0.8 点 | 3/6 | p = 1.0000 |
| S1 − 現 base | +17.2 点 | 1/6 | p = 0.4375 |
| **S1b − S1** | **−13.7 点** | **4/6**（1 本同点） | p = 0.1250 |

**S1b の判定は「戻った割合」に拠ります。** S1 の +50.5 点から現 base の +25.5 点へ向けて
**65.3% 戻りました**（登録した条件は半分以上）。**有意性の条件（p < 0.05）は満たして
いません** ―― ただし 6 clip で同点が 1 本出た時点で、**両側 p < 0.05 には原理的に
届きませんでした**（非 0 の差が 5 本なら最小の p = 0.0625）。**規則の前半は検出力の足りない
条件でした**（6 節）。

**なぜ S1 の中身は「音階練習」が主体になったか（確認済み）:** 学習は
`balance_speakers: true` で**話者ごとに等しく sampling** します（`weights = 1 / 話者ごとの件数`）。
そのため**時間の偏りは打ち消され、効くのは話者数の比**です。S1 はリツが時間の約 60% を
占めますが（9.8 h / 16.4 h）、sampling では 16 人中 14 人の VocalSet が 87.5% を占めます。

### 4.3 素材の棚卸し（実測）

**確認済み（2026-09-20）: 公開されている商用可の歌唱は 29.2 時間 / 40 話者でした。**
由来に懸念のある SingVERSE を除くと **20.1 時間 / 23 話者**です
（内訳は [データ要件](commercial-release-data.md) 4.1 節）。**量としては現 base と同規模**ですが、
**中身の大半が歌詞の無い発声練習**なので、S1 のとおり品質は再現できませんでした。

## 5. 訂正したこと（旧値・新値・原因）

**黙って書き換えず、経過を残した節には印を付けてあります。**

| 項目 | 旧（机上の調査） | 新（実測・実験） | 原因 |
|---|---|---|---|
| 商用可の歌唱 | 約 39 h / 24 話者以上 | **29.2 h / 40 話者** | SingVERSE の 18.14 h は**正解側と雑音側の合計**（片側 9.07 h）。NIT-SONG070 は論文表の 1.2 h に対し実測 0.526 h |
| **同規模なら作り直せるか** | 「素材の面では可能」 | **再現できない**（S1） | 量は揃っても**中身が歌詞の無い発声練習**だった |
| 利用者の素材の話者ラベル | 「無い」 | **ある**（`channel_id`。cover に限れば 1 channel = 1 話者） | sidecar JSON を読む前に推測した |
| 分離ボーカルの上限が別物 → 評価 | 「既存の数値と並べられない」 | **評価 test set を変えなければ比べられる** | 上限は**評価 clip** から作るので、学習素材を替えても共有できる |
| SingStyle111 のライセンス | CC BY 4.0 に見えた | **論文 PDF の record** だった | Zenodo の license は record のファイルに掛かる |
| S1 の素材時間 | 約 17.0 h（14 節の登録） | **約 16.4 h**（推定） | 波音リツ 10.41 h から、学習に入れなかった評価 3 曲 × 3 音源 = 9 曲ぶんを**引き忘れた**（141/150 で約 9.8 h）。**判定には影響しません**（比較は話者数の比で決まるため。4.2 節） |

## 6. 何が言えないか（限界）

- **どの実験も 1 回ずつ、評価は 6 clip**です。方向は出ましたが、**細かい数値は揺れ得ます**。
- **S1 と S1b は 50,000 step、現 base と P1 は 60,000 step**です。S1 はホストの障害で打ち切り、
  S1b は S1 に揃えました。根拠は「base の学習量は 30,000 → 60,000 で明瞭度が動かない」
  という既存の実測（p = 1.0）ですが、**厳密には条件が揃っていません。**
- **正規化統計は全実験で `m3c` の manifest を共有**しました。比較は公平ですが、P1・S1・S1b の
  推論は各自の学習分布からわずかにずれています。
- **「録音の質」と「1 人あたりの量」のどちらが効くかは切り分けていません**（4 節の仮説）。
- **「20 人 × 45 分」は現 base の形を基準にした目安**で、少なくて済むかは試していません。
- **比べたのは base どうし**です。target への fine-tune 後に差が縮むかは確かめていません
  （M4 では fine-tune で話者類似度が 77.9% → 91.4% に上がっています）。
- **規則の欠陥:** S1b の有意性の条件は、n = 6 では同点 1 本で原理的に届かないものでした。
  **次に規則を立てるときは、n から最小の p を先に計算すること。**

## 8. 途中で見つけて直した問題

**すべて失敗を再現するテストを書いてから直し、skill と CLAUDE.md に記録しました。**

**学習前に見つけた設計の誤り（3 件）:**

| 誤り | 影響（直さなかった場合） |
|---|---|
| 新しい base に変換先（リツ）が居ない | 比較そのものが成立しない |
| 評価に使う 3 曲が学習素材に混ざる | 「学習した曲」を測り、不当に良く出る（+1.0 点 対 +12.4 点） |
| 3 音源をまとめるときのファイル名衝突 | 150 本が黙って 100 本に減る |

**実装のバグ（TDD で修正）:**

| 症状 | 修正先 |
|---|---|
| 予算の端数が埋まらず、残りの tar を約 1 時間流し続けた | `tools/p1_corpus.py` の `budget_exhausted()` |
| 重いモデルを話者ごとに読み直していた（12 話者で 39 回） | `preprocess/svc/run.py` の `run_speakers()` |
| 有声 phrase が 0 の話者 1 人で全体が落ちた | 同上（飛ばして件数を報告、`--resume`） |
| 取得スクリプトを `runpy` で呼び、兄弟 import で失敗 | `tools/s1_corpus.py` |
| macOS のリソースフォーク（`._*.wav`）を音声として開いた | `tools/s1_corpus.py` の `is_audio_member()` |
| 題名から曲名を作る heuristic が実データで 2 件誤った | `preprocess/svc/sidecar.py`（限界も記録） |

**運用の失敗:**

| 失敗 | 対処 |
|---|---|
| `create` が `success: false` を返したのに作られており、6 時間課金 | `instances` を色コードを外して必ず読む（[vast skill](../.claude/skills/vast-instance/SKILL.md) 3e 節） |
| **起動待ちが認証エラーを握りつぶし、タイムアウトも無く、約 4 日課金** | **`tools/vast.py wait-ssh`**: 認証拒否とタイムアウトで止まる（同 3f 節） |
| 回収スクリプトが「checkpoint がまだ無い」を接続失敗と数えて止まった | SSH の失敗は終了コード 255 だけで判定 |
| gated な素材の HF token を渡し忘れた | 401 で即座に止まったので数分で復旧 |
| P1 の shard manifest を破棄前に回収し損ねた | 評価は `m3c` の manifest を全実験で共有（6 節） |

**一般則: バックグラウンドの待ちは、成功だけでなく失敗の終端でも止まること。**
止まらない待ちは、セッションが切れると課金だけを残します。
